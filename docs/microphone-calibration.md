# マイク音量メーター・しきい値提案

## 操作

1. 曲と利用環境（DAM／JOYSOUND／自宅テスト）を選ぶ。
2. 「雑音・伴奏の測定としきい値の提案」を開く。
3. PC・カラオケ機器の伴奏を止め、静かにして「雑音を4秒測定」を押す。
4. PC・カラオケ機器から冒頭の小さい伴奏を流し「伴奏を4秒測定」を押す。通常アプリのYouTubeは自動再生しない。
5. 両方の統計と説明を確認する。候補が出た場合だけ、必要なら「この値を採用」を押す。
6. 曲・利用環境の「設定を保存」を押す。採用だけでは永続保存しない。手動しきい値入力も従来どおり利用できる。
7. 測定終了でマイクを解放するため、通常の「検知を準備」から事前手動再生をやり直す。

測定開始時に既存の再生・検知を停止する。測定中は曲選択・環境変更・設定変更・通常の準備を無効化する。
「測定を中断」または「すべて停止」で中断できる。画面非表示・終了時にも停止する。マイク取得・解放が未完了なら次の取得は始めない。
4秒はマイク取得完了後から数える。測定結果・候補はこの画面のメモリと診断ログだけに保持し、ブラウザ再読込で消える。

## RMSとメーター

既存のWeb AudioアダプターのRMS（sqrt(mean(sample²))、上限1）をそのまま購読する。
音検知・メーター・測定は同じマイクleaseを共有し、メーター用のgetUserMediaは呼ばない。
通常の検知・再生ロジックを保ち、メーター購読はマイク保持中も続ける。音声をdestinationへ接続しない。

表示は最大10Hz、現在値としきい値は共通のRMS 0〜1。小音量を見やすくするため幅のみ平方根尺度を使い、その旨を明示する。
未取得・解放後・入力中断・1秒以上観測がない状態では音量バーを表示せず、未測定または観測待ちと表示する。
入力元は取得した音声トラックのlabelを表示する。未提供・例外時は「不明」。名前から本体・イヤホンと断定せず、デバイス切替機能やBluetooth経路の制御は追加しない。

## 測定・提案アルゴリズム

- 取得済みマイクから4秒間のRMSを集め、中央値、P10、P90、最大値、観測数を算出する。
- 分位点はソート後の線形補間。同一時刻・逆行時刻は重複観測として採用しない。
- 20観測以上、観測時刻の広がり3秒以上、途中・末尾に500ms超の無観測がないことを要求する。タイマーが1秒超遅延した場合も失敗扱い。
- 不正なRMSや入力中断はエラーにし、資源を解放する。無音でも継続観測できていれば統計を記録する。
- バッファ上限1000観測（通常の画面更新頻度なら4秒で約240観測）。生音声は保存しない。
- noise=P90(雑音)、music=P10(伴奏) とし、差 music-noise が max(0.005, noise×0.25) 以上なら (noise+music)/2 を小数点6桁に丸めて提案する。
- 突発音の最大値は候補計算に使わず、観察用に併記する。ただし大きな雑音が頻繁に続く場合はP90にも反映する。
- 分布の重なり・小差・ほぼ無音の伴奏では候補を出さない。伴奏冒頭の無音・弱音を含めると候補が出ないこともあり、安全側の結果として扱う。
- これは音量差によるヒューリスティックであり、曲識別・周波数解析・検知成功・実発音同期の保証ではない。検知継続時間は従来値を維持する。

## 保存・安全性・診断

提案は自動採用しない。採用はthresholdフィールドだけを変更し、開始位置・補正・待機期限・マイク保持設定に触れない。
既存の曲・環境別保存を使用する。しきい値のフィールドは変更しない。現在は開始トリガー対応のv3保存・バックアップを使い、v2・v1・旧HTML0.6も取り込める。
測定結果は開始時の動画ID・環境に対応付け、異なる曲・環境の候補を適用しない。曲選択では測定を中断し結果をリセットする。
再測定開始時には同種の古い結果を消し、再測定失敗時に以前の値を誤提案しない。

診断JSONには measurement.start、measurement.mic.acquire、measurement.acquired、measurement.result、measurement.suggestion、measurement.adopted、measurement.finished、measurement.release.failed を必要時に記録する。
保存対象は統計・時刻・報告名・候補のみで、PCM・録音ファイル・音声内容は記録しない。ログは既存の上限付き診断リングを使う。

マイク取得は取消可能と仮定せず、取得待ちで中断した場合はAbortSignalを通知し、遅着leaseを解放する。
アダプターが中断に応答しない場合は取得待ちを継続表示し、終了まで新しい取得を拒否する。未解放状態を成功扱いしない。
解放失敗は表示し、明示再試行を提供する。解放が未完了なら3秒で注意表示するが、実処理の完了まで同じPromiseに合流し、並行releaseしない。

## 実機確認

iPhone SafariでのAudioContext起動・マイク許可・4秒間の観測、入力元の報告名、表示負荷、Bluetooth経路変更、測定後の通常事前再生・自動再開は今回未確認。
測定時と検知時で入力元や自動音量処理・位置が変わると推定が使えない場合がある。実際の店舗雑音、拍手、歌声、隣室の伴奏でもしきい値・継続時間を検証する。
