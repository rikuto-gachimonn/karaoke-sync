# React通常アプリの曲リスト

## 登録・選択・編集

- 曲名、アーティスト、11文字のYouTube動画IDを入力して「曲を登録」。曲名は必須、アーティストは空欄も可。
- 入力中の動画IDを使う場合は「新規入力に戻す（現在の動画ID）」。曲名・アーティストを入れて登録する。
- 現在の動画と同じIDを登録すると画面の同期設定を引き継ぐ。別IDでは、従来のReact専用保存設定があれば読み取りで引き継ぐ。
- 「この曲を選択」で動画IDと現在の機種の保存設定を読み込む。機種を切り替えると、その機種の設定を読み込む。
- 未保存の機種では、従来のReact専用設定があれば利用し、それもなければ初期値にする。別曲・別機種の同期位置は流用しない。
- 「編集」で曲名・アーティスト・動画IDを更新できる。ID変更時は確認し、既存同期設定を引き継ぐため開始位置を再確認する。
- 削除は確認後、その曲の曲リスト内の情報と機種別設定だけを削除する。旧HTMLと従来のReact専用設定は削除しない。
- 同じ動画ID、または全角半角・大文字小文字・連続空白を正規化した同名・同アーティストを重複として拒否する。
  別バージョンならタイトルに版名等を付けて区別する。アーティスト空欄同士はタイトルだけでは重複扱いしない。

曲選択時は前曲の停止と資源解放を待つ。マイク取得や資源解放が未完了なら、次曲の設定を適用せず案内する。
前曲の補正タイマー・検知・再生命令は既存のSessionController.stopで無効化する。
編集・削除・JSON復元は停止後だけ可能。曲変更・機種変更で未保存の画面編集は引き継がないので、必要なら先に設定を保存する。
事前手動再生→自動停止→音検知→自動再開の実装は変更していない。

## 設定保存

選択した曲を調整し「この曲・機種の設定を保存」を押す。DAM・JOYSOUND・自宅テスト（HOME）はそれぞれ独立して保存する。
開始トリガー、登録開始位置、歌声用開始位置、発声合図用開始位置、既存オフセット、補正方式、固定待機ms、位置補正Bのms、実効開始位置の主調整ms、再生方式、しきい値、継続時間、待機期限、マイク保持設定を含む。
保存は明示操作のみ。曲名等の登録・編集・削除は各ボタン操作で保存する。
曲未選択での手入力設定保存は従来どおりReact専用設定キーを使い、曲登録時に引き継げる。

| データ | localStorageキー |扱い |
| --- | --- | --- |
| 現行曲リスト | `karaokesync.app.library.v3` | 曲情報・開始トリガーと3環境別設定。明示保存で書込み |
| React v2曲リスト | `karaokesync.app.library.v2` | v3未作成時に読み取りのみで継承。削除・上書きしない |
| React v1曲リスト | `karaokesync.app.library.v1` | v3/v2未作成時に読み取りのみで継承。削除・上書きしない |
| 手入力動画の現行同期設定 | `karaokesync.app.sync-preferences.v3` | 開始トリガー・3環境と主調整。明示保存で書込み |
| React v2同期設定 | `karaokesync.app.sync-preferences.v2` | v3未作成時だけ読取り。削除・上書きしない |
| 従来のReact同期設定 | `karaokesync.app.sync-preferences.v1` | 既存の機能を維持。曲への取込は読取り、上書き移行しない |
| 旧HTML | `song_list`、`sync_<ID>`、`song_info_<ID>`、`detect_settings_<ID>` | 明示取込時だけ読取り。変更・削除しない |

現行の保存・バックアップは `{format:"karaokesync-library-v3",version:3,songs:[...]}`。React v2の `{format:"karaokesync-library-v2",version:2,songs:[...]}` も取り込める。旧React v1の `{format:"karaokesync-library",version:1,songs:[...]}` も取り込める。
各曲はvideoId、title、artist、profilesを持ち、profilesのDAM/JOYSOUND/HOMEに対応するinputとretainMicを格納する。伴奏記録は曲のaccompanimentRefに任意保存する。
未知バージョン・破損保存は自動初期化や上書きをせずエラーにする。
上限は1000曲、曲名・アーティスト各200文字、保存/バックアップ5MiB。一般的な個人利用の余裕と端末の処理・容量保護を両立する暫定値。
値は `src/library/model.ts` のlibraryLimitsで一元管理する。

## バックアップ・復元

1. 画面で調整した設定を先に保存する。曲リストJSONには未保存の画面編集や、曲登録していない手入力専用設定は含めない。
2. 「曲リストと保存済み同期設定をJSONで保存」でバックアップする。
3. 停止後、JSONファイルを選ぶ。全件を検証してからプレビューし、この時点では保存しない。
4. 新規曲は追加候補を選ぶ。重複動画では曲情報・DAM設定・JOYSOUND設定・自宅テスト設定ごとに上書きチェックを選ぶ。
   既存設定の上書きは初期状態では未選択。既存曲にない機種設定は追加候補として選択される。
5. 「設定の比較」で現在/取込の値を確認して「選択内容で復元（チェックした上書きに同意）」を押す。
6. 復元後は曲を選び直す。取り消しではデータを書き込まない。

全件検証・マージ後、一つのキーへのsetItemが成功した時だけ画面の曲リストも更新する。
形式エラー・重複衝突・容量不足で部分復元しない。別タブの変更を検出した場合は上書きを止め、再読込を案内する。
複数タブでの同時編集は避ける。旧データを自動取込する仕組みはなく、削除した曲が再起動で勝手に再取込されることはない。

## 旧HTMLからの移行（コードで確認した0.6形式だけ対応）

旧HTMLのcreateBackupDataは次の形を出力する。

```json
{
  "appName": "Karaoke Sync",
  "backupVersion": "0.6",
  "exportedAt": "...",
  "songs": [{
    "videoId": "M7lc1UVf-VE",
    "savedSec": "12.35",
    "songInfo": {"title": "曲名", "artist": "歌手", "service": "DAM"},
    "detectSettings": {"offset": -0.05, "threshold": 0.08}
  }]
}
```

- 旧HTMLでJSONを書き出し、通常アプリの復元欄で選ぶ。file://や別HTTPSオリジンのlocalStorageは通常アプリから直接読めない。
- 同じオリジンに旧キーがある場合だけ「このオリジンの旧localStorageを読んでプレビュー」も使える。
- 旧設定は動画単位で、serviceは単一の曲情報。機種別設定が二組あるとはみなさない。記録された機種だけへ割り当てる。
- service未選択/nullの曲情報の場合は、先に「旧データの機種未選択設定の移行先」を指定して読み込む。未知の機種文字列は拒否する。
- savedSec（秒文字列）を開始位置へ移す。detectSettings.offsetは秒なので1000倍してB位置補正msへ移す。
- 旧検知は最初のRMS超過で成立するため継続時間0msへ移す。thresholdは保存値を検証して引き継ぐ。
- 旧形式にない再生方式等は新アプリの初期値（事前再生方式、待機期限300秒、マイク保持）を設定する。
- 位置未保存nullは初期値0秒とし、プレビューで再設定が必要と警告する。空の曲名は動画ID付きの「未設定」表示にする。
- 元の旧キー・旧ファイルは保持する。非対応バージョンや不正数値・重複データは推測で一部だけ変換しない。

## 自宅テストと3段階の実効開始位置調整

1. 曲を選び、「カラオケ機種・利用環境」で「自宅テスト（PC＋スピーカー）」を選択する。
2. 必要なら「曲管理→編集」で、PC側で使う伴奏のYouTube URLまたはIDを記録する。これはメモだけで、PCを自動操作しない。
3. 最初は詳細設定の登録開始位置を設定し、補正方式は「基準」、固定待機・Bは0で試す。
4. 停止中にメイン画面の±1秒・±0.1秒・±0.01秒を使って実効開始位置を調整する。
   ＋は動画内容の先へ、−は前へ戻す。基準・A・B・A＋Bのすべてで主調整が有効。
5. 「詳細設定→この曲・機種の設定を保存」で、その曲のHOME設定だけを保存する。DAM/JOYSOUNDの既存値を流用・上書きしない。
6. 「検知を準備」→YouTubeを直接タップ→自動停止・音検知待機→PCで伴奏を再生する。
   イヤホンの実発音と出力先を観察し、調整し直す場合は先にすべて停止する。

### 計算方法

```text
基準位置 = 歌声方式では歌声用開始位置、発声合図では合図用開始位置、他は登録開始位置（未指定の個別位置は登録開始位置）
従来開始位置ms = max(0, round(基準位置×1000) + round(旧オフセット秒×1000))
有効Bms = B/A＋B方式の位置補正（基準/Aでは0）
指定実効開始位置ms = max(0, 従来開始位置ms + 有効Bms + startAdjustmentMs)
実際の要求位置 = 指定実効開始位置を0〜取得済み動画長へ制限
```

主調整は符号付き整数msで保持し、ボタンは5000/1000/100/10msを加減する。旧位置・旧オフセット・Bへ同じ値を重複保存しない。
下限に達したボタン操作は0秒で止まり、余分な負方向の押下を蓄積しない。
動画長は停止中には確定しないため、画面は上限制限前の指定値を表示し、初回のシーク要求時に動画範囲へ制限する。
動画長を取得できない場合は範囲を推測せず、既存の補正制御に従いエラー停止する。終了位置ぴったりではENDEDになり得る。
主調整の安全上限は±24時間（86400000ms）。変更は停止中だけ可能で、次回の準備スナップショット・検知後の初回再生に適用する。
再生中の追従シークは追加しない。従来方式でも主調整が非0なら検知時に一度シークするため、動画長が必要。
10msは設定刻みであり、Bluetooth実発音・同期精度の保証ではない。

従来開始位置の負数クリップ順序は互換性のため維持する。旧データにstartAdjustmentMsがない場合は0として扱い、
旧HTML 0.6のoffset秒→Bのmsという既存変換も変更しない。旧オフセットと比較Bの操作は「互換設定」にまとめた。

### v3への移行と保護

通常アプリはv3保存先を優先し、v3がまだない場合だけv2、v2もなければv1を読み取りで引き継ぐ。起動や環境選択だけでは保存しない。
明示保存後もv2/v1キーと旧HTMLデータを残す。v3が空の曲リストであっても旧曲を自動再取込しない。破損v3から旧形式へ黙って戻らない。
v3と旧版を別々のアプリで同時編集した場合、v3作成後の旧版側の変更は自動反映しない。バックアップのプレビューで明示的に取り込む。
内部の共通曲モデルは既存マージ・検証処理と共有し、外部v2/v3形式との変換はencode/decodeで行う。
旧v1と旧HTML 0.6の設定は、記録されたDAM/JOYSOUNDへだけ取り込み、HOMEに自動複製しない。
旧機種未選択のデータだけは、プレビュー前にHOMEを移行先として明示選択することもできる。
既存曲へHOME設定だけを追加する場合、復元プレビューでHOMEだけを選べばDAM/JOYSOUNDを保持する。
伴奏記録は曲情報の上書き選択に含み、v1取込で記録が存在しない場合は既存の伴奏記録を消さない。

iPhone Safariの今回の追加UI、自宅環境での実マイク・Bluetooth実発音・10ms調整の聴感効果は未確認。

### 操作性改善：通常・詳細・開発者向け設定

- 通常画面：4段階の実効開始位置調整、音量しきい値、検知継続時間、曲・環境別の保存／復元。
- 詳細設定：登録開始位置、動画ID、再生方式。新規の実接続設定では事前再生方式を推奨する。既存の従来方式は維持する。
- 開発者向け設定（初期状態は閉じる）：補正方式、A待機、B補正、既存オフセット、待機期限、検知後のマイク保持／解放。
- 折りたたみは表示だけを変え、入力フォームをアンマウントしない。開閉による初期化・保存は行わない。すべての設定変更は停止中のみ。

待機期限の優先順位は、選択曲・環境の保存済み明示値 → 期限未指定時の30分（1800000ms）。
手入力動画も既存の保存／復元手順で明示値を優先する。新規設定は30分。
旧形式・旧バックアップの明示値（例：5分）は維持し、起動・選択・折りたたみ開閉だけで書き換えない。
期限未指定の旧データはフィールド自体を追加保存せず、実行時だけ30分を採用する。
通常画面は現在の有効期限を表示するだけとし、変更は開発者向け設定で1〜1800秒の範囲内に限る。
無制限待機は受け付けない。期限切れでは「検知待機期限超過」と表示し、既存の終了処理で検知・マイク・プレイヤーを解放する。
検証ページ①〜⑦の従来の期限上限・動作は変更しない。

検知後のマイクは新規設定で保持を推奨する。保存済みの解放設定は保持へ変更しない。
今回のiPhone実測を根拠とする推奨であり、すべての端末やBluetooth機器への適合保証ではない。
保持でも停止・待機期限超過時には解放する。設定変更自体でマイクを取得しない。
現在のバックアップは開始トリガー対応のv3。v2・v1・旧HTML0.6も既存の検証・プレビューを経て取り込む。
今回の画面整理と30分待機のiPhone実機確認は別途必要。
