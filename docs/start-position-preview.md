# 開始位置設定の集約・ピー音プレビュー

## 設定と保存

「実効開始位置の調整」に、補正前の歌い始め入力、確認プレビュー、検知時間の自動補正量、手動補正/±ボタン、補正後の候補、主調整リセット、開始位置設定の保存を集約した。歌い始め入力は新しいSingingPositionInputへ同じ表示/変更処理を移しただけで、音声検知欄には重複して残していない。音声検知欄にはモード・しきい値・継続時間・自動補正ON/OFF・全曲適用を維持する。

保存ボタンは既存saveCurrentSettingsを再利用するため、同じ曲/機種/モードの現在設定全体を保存する。新しい保存形式や位置専用の別キーは作らない。通常設定の保存/復元ボタンも維持する。リセットは従来どおりstartAdjustmentMsだけを0にし、基準位置・検知時間・自動補正は変更しない。playbackPlan、検知器、補正/推奨値計算、バックアップ、旧データの移行処理は変更しない。

## プレビューの構成と発音

PositionPreviewControllerは通常のSessionControllerとは別の一時的な所有者として、既存YouTubePlayerアダプターと同じ可視youtube-hostを排他的に使用する。マイク/検知器を生成・取得せず、通常試行・補正履歴・曲設定にも記録しない。対象時刻はtriggerPosition(input)だけを渡し、同期補正・D・S等を渡さない。

- 基準30秒なら28秒から再生し、基準通過を観測した時に1回だけ確認音を要求、32秒付近または動画末尾で終了。基準1秒なら0秒から、基準0は先頭近傍の最初の有効観測で確認音を要求する。
- 動画長が不明、基準が動画長以上、入力不正なら鳴らさず停止する。
- Web Audioの起動は最初のボタン操作内でAudioContextを作りresumeを呼ぶ。880Hzのサイン波、ピークgain 0.06、短い立上り/立下り、160msで停止する。一度鳴ったインスタンスでは再発音しない。停止時はノードを止めて切断し、AudioContextをcloseする。
- 端末/ブラウザの既定出力を使用し、setSinkId、マイク取得、既存Bluetooth設定の変更はしない。YouTubeのメディア音声とWeb Audioが必ず同じBluetooth経路/遅延になるとは保証できない。

## 時刻監視と精度

PLAYINGを確認した後にreadPlaybackState/getCurrentTimeを順番に読み、終了した読取りから50ms後に次の監視を予約する（最大約20Hz、重複ポーリングなし）。画面上の参考時刻の更新は約4Hzに抑え、通過/終了の通知だけを別途即時更新する。参考時刻はaria-liveを無効にし、毎回読み上げない。補間位置や壁時計だけで確認音を予約しない。

最初の時刻がシーク前の古いキャッシュで開始候補より前の場合は、最大1秒だけ開始付近の更新を待つ。開始位置より大きく先へ飛んだ初回値は信用しない。以降は前回値との逆行や大きな飛び、300ms超の監視中断を検出したら停止する。通常のAPI量子化を許容するため、前進の許容はmax(0.30秒, 観測経過時間×再生速度+0.15秒)。指定時刻を通過しても0.25秒より遅ければ確認音を鳴らさず中止する。

これらは誤発音を減らす安全側の判定であり、APIの精度保証ではない。小さなシークとAPIキャッシュの更新を完全には区別できない。通常の動画速度、APIキャッシュ、端末負荷、Web Audio/YouTubeの出力遅延で一致しない可能性がある。実際のYouTube音声とピー音をサンプル精度で同期できるとは説明しない。

再生後のbuffering/paused/cued、動画エラー、不正/取得不能な時刻、バックグラウンド移行では中止。再生/確認音の準備は15秒、明示再生待ちも15秒、PLAYING後は12秒の上限を設け、時刻停止や応答未完了でも無期限に監視しない。再生がブロックされた場合は確認音を鳴らさず、可視プレイヤーの▶または「プレビューを再生」の明示操作を案内する。広告を強制スキップ/ブロックする処理は追加しない。広告の状態をこのAPIで確実に判別するものでもない。

## 排他・停止・回収

プレビュー開始は通常セッションが資源を持たず、測定/マイクの取得解放もない場合だけ許可する。プレビューがbusyの間、通常prepareと測定の資源取得を内部でも拒否し、UIの準備・測定・曲切替・設定変更も無効にする。起動操作の同時実行で二重プレイヤーを作らない。

「すべて停止」はプレビュー、測定、通常セッションへ停止を要求する。プレビューの監視/期限タイマー・購読を解除し、確認音を閉じ、可視プレイヤーの一時停止を試してから破棄する。準備/時刻読取りが遅着してもactiveな所有者を確認し、停止済みの処理から再生・発音しない。

資源解放が失敗した場合は所有者とbusyを残して通常の検知をロックする。「すべて停止」で再試行できる。解放が未完了なら2.5秒後にその旨を通知し、完了が確認されるまで新しい所有者を開始しない。終了時に通常の検知を自動開始したり、既存設定を保存したりしない。元の通常セッションの安全な停止/待機状態を維持する。
